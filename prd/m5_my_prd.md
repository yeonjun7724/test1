# PRD — 불법건축물 허가 대조기 (LH 불법건축물 탐지 POC 축소판)

| 항목 | 내용 |
|---|---|
| 직군·부서 | 건축 · 점검·관리 담당 `[가정]` |
| 결과물 형태 | HTML 파일 하나로 된 웹앱 — `tools/m5_permit_filter.html`, GitHub Pages 배포 |
| 입력 데이터 | 가상 표본(변화 지점 목록·인허가 목록)을 화면에 붙여 넣거나 직접 입력 |
| 작성 | 2026. 11. 25.(수) · 실습용 PRD |

## 1. 프로젝트 개요

- 해결하려는 문제: 점검 인력이 한정돼 전수 확인이 어렵고, 자료를 사람이 눈으로 비교하는 방식이라 속도가 느리다.
- 배경: 관리 대상이 늘어나는 가운데, 내부에서 AI·영상 분석 도입 요구가 있어 POC로 검증하려 한다.
- 기대 변화: 점검 인력이 자료를 눈으로 비교해 의심 지점을 찾음 → 의심 지점을 먼저 추려 주고, 사람은 그것만 확인한다.
- 이번 범위: 위성·항공사진 비교(기능 1)는 이번에 만들지 않는다. 변화 지점 목록이 이미 있다고 보고, **허가 없는 변화만 걸러 내는 단계(기능 2)** 를 먼저 만든다. `[가정]`

## 2. 사용자 분석

- 주 사용자: 본사·지역본부 관리 담당자(점검 전에 볼 곳을 정하는 사람), 현장 점검 담당자(추린 지점을 확인하는 사람)
- 사용 맥락: 관리 담당자가 사무실 PC 브라우저에서 점검 전에 연다. 현장 담당자에게는 결과 화면을 캡처·출력해 전달한다. 모바일 화면은 이번에 만들지 않는다.
- 현재 방식과 한계: 위성·항공사진이나 지도에서 과거와 현재를 눈으로 비교한다. 사람이 직접 비교해 느리고 전수 확인이 어렵다.

## 3. 기능 요구사항

| 구분 | 기능 | 설명 |
|---|---|---|
| **MVP(이번)** | 허가 대조 필터링 | 변화 지점 목록과 인허가 목록을 지번으로 맞춰 보고, 허가 기록이 없는 변화만 걸러 낸다. |
| 다음 | 변화 지점 자동 탐지 | 과거·현재 위성·항공사진을 비교해 변화 지점을 찾는다. 사진 처리가 필요해 이번에 미룬다. |
| 다음 | 지도 표시·위험도 정렬 | 지도 위에 표시하고 위험도 순으로 정렬한다. 지도 라이브러리 없이 만들 수 없고 위험도 기준도 없어 미룬다. |
| 제외 | 관리자용 현황 화면 | 인터뷰에서 이번 POC 제외로 정했다. |

- 차별점: 사진 비교와 대장·인허가 대조를 한 번에 처리해 허가 없는 변화만 추려 주는 것이 최종 목표다. 이번 MVP는 그중 대조 단계만 검증한다.

## 4. 비기능 요구사항

- 결과물 형태: `tools/m5_permit_filter.html` 파일 하나. 서버·로그인·설치·외부 라이브러리·외부 전송 없음. 스타일·스크립트는 파일 안에 넣는다. GitHub Pages로 배포한다.
- 사용 환경: 사무실 PC 브라우저. 모바일 앱·여러 파일 구성은 쓰지 않는다.
- 데이터 민감도: 가상 표본만 쓴다. 실제 소유자 이름·주소·연락처는 넣지 않는다. 입력은 브라우저 밖으로 나가지 않는다.
- 저장: 브라우저 안 localStorage 키 하나 `m5_permit_filter`에 마지막 입력값을 저장한다. JSON 백업 내보내기·가져오기 버튼을 둔다. `[가정]`
- 제약: 외부 클라우드·외부 API 사용 불가. 기간·인력·예산: {확인 필요: 기간·인력·예산}

## 5. 성공 지표

- 성공 모습: 가상 표본을 넣으면 허가 없는 변화 지점만 따로 나와 눈으로 대조하는 일이 줄어든다.
- 핵심 지표(표본으로 판정): 아래 S1~S3 통과.
- 참고 지표(표본으로 판정할 수 없어 이번 판정에서 제외): AI 의심 지점의 정확도 목표치 {확인 필요: 정확도 목표치}, 기존 점검에서 놓친 건 추가 발견 건수, 점검 시간 단축.

### 성공 시나리오

| # | 이렇게 넣으면 | 화면에 이것이 보인다 |
|---|---|---|
| S1 | 예시 불러오기로 변화 지점 10건·인허가 6건을 넣고 '대조'를 누르면 | 허가 없음 4건, 허가 확인 5건, 확인 필요 1건으로 나뉘어 보이고 합이 10건이다. `[가정]` |
| S2 | 변화 지점의 지번이 인허가 목록에 있는 지점을 넣으면 | 그 지점은 '허가 없음' 목록에 나오지 않고 '허가 확인'에 인허가 번호와 함께 나온다. |
| S3 | 지번이 비었거나 형식이 다른 줄을 섞어 넣으면 | 그 줄은 '확인 필요'로 따로 나오고 줄 번호와 사유가 보이며, 건수 합계에서 빠지지 않는다. |

## 6. 사용자 여정

1. 관리 담당자가 `m5_permit_filter.html`을 연다.
2. 입력 화면에서 변화 지점 목록과 인허가 목록을 붙여 넣는다(또는 '예시 불러오기').
3. '대조'를 누르면 결과 화면으로 넘어간다.
4. 허가 없는 변화 목록을 확인하고, 결과 화면을 캡처·출력해 현장 담당자에게 전한다.
5. 필요하면 '백업 내보내기'로 입력값을 JSON 파일로 받아 둔다.

## 7. 화면과 입력

### 화면 (2개)

| 화면 | 하는 일 |
|---|---|
| ① 입력 | 변화 지점 목록·인허가 목록 붙여 넣기, 예시 불러오기, 대조 실행, 입력값 저장·백업 내보내기·가져오기 |
| ② 결과 | 건수 요약(허가 없음·허가 확인·확인 필요·합계), 허가 없음 목록, 허가 확인 목록(인허가 번호 포함), 확인 필요 목록(줄 번호·사유) |

### 입력 (가상 표본만)

- 방식: 붙여 넣기(쉼표로 구분한 줄) 또는 직접 입력. 파일 선택은 쓰지 않는다. `[가정]`
- 변화 지점 목록 열: `지점ID, 지번, 변화유형, 변화면적(㎡)`
- 인허가 목록 열: `인허가번호, 지번, 허가용도`
- 대조 기준: 지번이 같으면 허가가 있는 것으로 본다. 면적·용도 비교는 이번에 하지 않는다. `[가정]`

## 8. 수용 기준

| # | 기준 | 확인 방법 | 결과 |
|---|---|---|---|
| AC1 | 예시를 넣으면 S1의 건수(4·5·1, 합 10)가 나온다 | 결과 화면 건수 요약 확인 | ☐ 통과 ☐ 수정 |
| AC2 | 허가 확인 지점에 인허가 번호가 함께 보인다 | 허가 확인 목록 확인 | ☐ 통과 ☐ 수정 |
| AC3 | 지번이 비었거나 형식이 다른 줄은 확인 필요로 나뉘고 사유가 보인다 | 오류 줄을 섞어 넣고 확인 | ☐ 통과 ☐ 수정 |
| AC4 | 세 목록의 합이 입력 줄 수와 같다 | 요약의 합계와 입력 줄 수 대조 | ☐ 통과 ☐ 수정 |
| AC5 | 새로 고침 후에도 마지막 입력이 복원된다 | 입력 후 새로 고침 | ☐ 통과 ☐ 수정 |
| AC6 | 백업을 내보내고 가져오면 같은 입력이 복원된다 | JSON 내보내기 후 가져오기 | ☐ 통과 ☐ 수정 |
| AC7 | 네트워크 요청이 없고 외부 라이브러리를 쓰지 않는다 | 브라우저 개발자 도구 네트워크 탭, 파일 안 `src`·`href` 확인 | ☐ 통과 ☐ 수정 |

## 9. 위험 요소

- 지번 표기가 달라(공백·하이픈) 같은 필지를 다른 곳으로 보면 허가 있는 지점이 '허가 없음'에 나온다 → 공백 제거 등 표기를 맞춘 뒤 비교하고, 맞추지 못하는 줄은 '확인 필요'로 보낸다.
- 지번만 맞춰 보므로 허가 면적을 넘는 증축은 걸러 내지 못한다 → 다음 단계로 둔다.
- 실제 대장·인허가 자료는 개인정보가 섞일 수 있다 → 이번에는 가상 표본만 쓴다. 실자료 적용 시 마스킹 기준 {확인 필요: 마스킹 기준}이 먼저 필요하다.

## 10. 판단 경계

- 이 도구는 불법건축 여부를 판정하지 않는다. '허가 없음'은 점검 후보일 뿐이며 최종 판단은 담당자가 한다.
- 가상 표본 결과이므로 실제 단지·필지에는 적용하지 않는다.

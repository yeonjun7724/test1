# PRD — 하자 접수대장 검증기

| 항목 | 내용 |
|---|---|
| 직군·부서 | 건축 · 가상주택공사 누리사업본부 주택품질부 하자관리팀 |
| 결과물 형태 | 업무 자동화 도구 — `scripts/defect_ledger_check.py` + CLAUDE.md 규칙 |
| 입력 데이터 | `inputs/m2/A-M2-01_하자접수대장_week1.csv` |
| 작성 | 2026. 11. 12.(목) · 실습용 예시 PRD |

## 1. 프로젝트 개요

- 해결하려는 문제: 관리사무소·콜센터·입주민 앱·현장 방문 접수분을 손으로 합친 대장에 같은 건이 두 번 들어가거나 표기·단위가 섞여, 그대로 세면 건수와 면적이 틀린다.
- 배경: 담당자가 매주 대장을 눈으로 정리한 뒤 집계한다. 회의 전 요약에 대장 줄 수를 그대로 적어 회의에서 건수가 두 번 바뀐 적이 있다.
- 기대 변화: 눈으로 찾고 손으로 정리 → 같은 기준으로 걸러 낸 집계 결과와 제외·수정 기록을 매주 같은 명령 하나로 받는다.

## 2. 사용자 분석

- 주 사용자: 하자관리팀 접수대장 담당자(매주 집계 결과를 회의 자료·협조전에 넘기는 사람)
- 사용 맥락: 매주 월요일 오전, 지난주 대장을 받아 Claude Code 세션에서 실행한다.
- 현재 방식과 한계: 엑셀 정렬로 중복을 찾는다. 어떤 행을 왜 뺐는지 남지 않아 다른 사람이 검산할 수 없다.

## 3. 기능 요구사항

- 핵심 기능(우선순위 순)
  1. 규칙별 검사 — 중복·단위 섞임·합계 행·비표준 표기를 정해진 순서로 찾아 행마다 처리(포함·수정 후 포함·제외)를 정한다.
  2. 집계 — 정상 행으로 공종별·처리상태별 건수, 긴급 건수, 보수 면적 합계(㎡)를 낸다.
  3. 기록 — 제외 행(원본행·사유·원본값)과 수정 행, 실행 명령을 파일로 남긴다.
- 차별점: 모든 제외·수정에 규칙 이름과 원본 값이 남아 다른 사람이 같은 결과를 다시 낼 수 있다.

## 4. 비기능 요구사항

- 사용 환경: Claude Code 클라우드 세션, Python 표준 라이브러리만 쓴다(추가 설치 없음).
- 데이터 민감도: 가상 자료만 쓴다. 데이터를 외부로 보내지 않는다.
- 제약: 원본 CSV는 읽기만 한다. 결과 CSV는 엑셀에서 한글이 깨지지 않게 UTF-8(BOM)로 쓴다. 반올림은 사사오입, 최종 합계에서 한 번만 한다.

## 5. 성공 지표

- 성공 모습: 대장을 넣으면 집계 결과와 정리 근거가 함께 나와 손 정리가 없어진다.
- 핵심 지표: 8절 수용 기준 전 항목 통과.

## 6. 사용자 여정

1. 지난주 대장 파일을 `inputs/`에 둔다.
2. "scripts/defect_ledger_check.py로 이번 주 대장을 검사해 줘"라고 지시한다.
3. 규칙별 제외·수정 행 수와 집계 결과를 확인한다.
4. 검산표 공개값과 대조하고 결과를 PR로 병합한다.

## 7. 단계별 개발 우선순위

- MVP: 규칙별 검사 + 정상 건수 + 제외 행 기록
- 다음: 공종별·처리상태별·긴급 집계, 보수 면적 합계, 실행 기록
- 추후: 다른 주차 자료 형식 점검, 다음 주 대장과 누계 비교

## 9. 위험 요소

- 대장의 합계 행을 데이터로 세면 건수와 면적이 부풀려진다.
- 표기를 맞추기 전에 중복을 판정하면 같은 건을 다른 건으로 본다 → 표기를 맞춘 뒤 판정한다.
- 행마다 반올림한 값을 더하면 합계가 기대값과 0.1 차이 날 수 있다 → 마지막에 한 번만 반올림한다.

## 10. 판단 경계

- 이 도구는 하자 판정·구조 안전 판정·보상·계약금액을 확정하지 않는다. 결과는 담당자가 확인한다.
- 제외 행을 다시 포함할지는 담당자가 정한다.

# PRD — 불법건축물 의심 건 탐지 도구

| 항목 | 내용 |
|---|---|
| 직군·부서 | 건축 · LH 건축 담당 |
| 결과물 형태 | 업무 자동화 도구 (의심 건 선별 스크립트 + CLAUDE.md 규칙) — 구체 파일명은 입력 자료 확정 후 정함 |
| 입력 데이터 | 확정 필요: 관리 단지 건축물대장·인허가 도면 목록, 현장 점검 기록 (아래 "열린 질문" 참고) |
| 작성 | 2026. 11. 23.(월) · 초안 (prd_memo 3줄 메모를 prd/model_prd_arch.md 양식으로 확장) |

## 1. 프로젝트 개요

- 해결하려는 문제: 관리 단지의 불법건축물(무단 증축·용도변경 등)을 현장 순찰과 수작업 도면 대조로 찾느라 시간이 오래 걸리고 누락이 생긴다.
- 배경: 담당자가 인허가 도면·건축물대장과 현장 상태를 눈으로 대조한다. 단지 수가 많아 점검 주기가 길어지고, 무엇을 어떤 근거로 의심했는지 기록이 남지 않는다.
- 기대 변화: 전수 눈 대조 → 같은 기준으로 걸러 낸 의심 건 목록과 근거를 받아, 담당자는 우선순위 높은 건만 현장 확인한다.

## 2. 사용자 분석

- 주 사용자: LH 건축 담당자 (관리 단지 점검·민원 대응 실무자)
- 사용 맥락: 정기 점검 전이나 민원 접수 시, 대상 단지 자료를 넣고 Claude Code 세션에서 실행한다.
- 현재 방식과 한계: 도면·대장을 수작업으로 대조하고 현장을 순찰한다. 누락 여부를 확인할 수 없고, 점검 근거를 다른 사람이 검산할 수 없다.

## 3. 기능 요구사항

- 핵심 기능(우선순위 순)
  1. 규칙별 대조 — 대장·도면상 면적·층수·용도와 현황 자료를 정해진 규칙으로 비교해 불일치 건을 찾는다.
  2. 의심 건 목록 — 불일치 유형(증축·용도변경 등)과 정도별로 우선순위를 매겨 단지별로 낸다.
  3. 기록 — 의심으로 본 근거(규칙 이름·비교한 두 값)와 의심 아님으로 본 건의 사유, 실행 명령을 파일로 남긴다.
- 차별점: 모든 판정에 규칙 이름과 원본 값이 남아 다른 사람이 같은 결과를 다시 낼 수 있다.

## 4. 비기능 요구사항

- 사용 환경: Claude Code 클라우드 세션, Python 표준 라이브러리 우선(추가 설치 최소화).
- 데이터 민감도: 실제 단지·소유자 정보가 섞일 수 있다. 개인정보는 제외하거나 가리고, 외부 전송 전 반드시 확인한다. (확정 필요)
- 제약: `inputs/` 원본은 읽기만 한다. 결과는 `outputs/m{모듈 번호}/`에 새 파일로 낸다. 결과 CSV는 엑셀에서 한글이 깨지지 않게 UTF-8(BOM)로 쓴다. 면적 반올림은 최종 합계에서 한 번만 한다.

## 5. 성공 지표

- 성공 모습: 대상 단지 자료를 넣으면 의심 건 목록과 근거가 함께 나와, 전수 눈 대조가 없어진다.
- 핵심 지표(예/아니오 판정)
  - 과거 확정된 불법건축물 사례 중 도구가 의심 건으로 잡아낸 비율이 80% 이상인가?
  - 담당자 1명의 단지당 점검 시간이 기존 대비 50% 이상 줄었는가?
  - 80%·50%는 임시 기준이며 담당자가 확정한다.

## 6. 사용자 여정

1. 점검 대상 단지의 대장·도면·현황 자료를 `inputs/`에 둔다.
2. 도구 실행을 지시한다.
3. 단지별 의심 건 수와 우선순위 목록을 확인한다.
4. 상위 건만 현장 확인하고, 결과(위반 확정·아님)를 기록한다.
5. 확정 결과를 다음 실행의 검증용 사례로 쌓는다.

## 7. 단계별 개발 우선순위

- MVP: 면적·층수 불일치 규칙 대조 + 의심 건 목록 + 근거 기록
- 다음: 용도변경 규칙, 우선순위 점수, 단지별 집계
- 추후: 항공·위성 사진 등 영상 기반 탐지, 과거 확정 사례로 정확도 자동 점검

## 8. 수용 기준

| # | 기준 | 확인 방법 | 결과 |
|---|---|---|---|
| AC1 | 의심 건마다 규칙 이름과 비교한 두 값이 결과 파일에 있다 | 결과 CSV 행별 근거 칸 확인 | ☐ 통과 ☐ 수정 |
| AC2 | 의심 아님으로 뺀 건은 사유가 기록에 남는다 | 실행 기록 표 확인 | ☐ 통과 ☐ 수정 |
| AC3 | 과거 확정 사례 중 의심 건으로 잡은 비율이 80% 이상이다 | 확정 사례 목록과 의심 목록 대조 | ☐ 통과 ☐ 수정 |
| AC4 | 단지별 의심 건 수가 두 번째 방법(엑셀 등) 집계와 같다 | 검산 파일 대조 | ☐ 통과 ☐ 수정 |
| AC5 | 면적 값은 ㎡ 단위, 소수 1자리(최종 1회 반올림)다 | 결과 CSV 면적 열 + 엑셀 검산 | ☐ 통과 ☐ 수정 |
| AC6 | 원본 파일을 수정하지 않는다 | PR diff에 inputs/ 변경 0 | ☐ 통과 ☐ 수정 |
| AC7 | 같은 입력으로 두 번 실행하면 결과 파일이 같다 | 두 번 실행 후 diff | ☐ 통과 ☐ 수정 |
| AC8 | 담당자 1명의 단지당 점검 시간이 기존 대비 50% 이상 줄었다 | 도입 전후 소요 시간 비교 | ☐ 통과 ☐ 수정 |

## 9. 위험 요소

- 허가 도면과 현황의 단위·표기·기준일이 달라 정상 건을 의심으로 잡을 수 있다 → 표기를 맞춘 뒤 비교한다.
- 오탐이 많으면 담당자가 도구를 믿지 않게 된다 → 근거를 함께 보여 주고 우선순위로 거른다.
- 누락(미탐)은 결과에서 보이지 않는다 → 과거 확정 사례로 잡아낸 비율을 주기적으로 점검한다.
- 개인정보·소유자 정보가 결과에 섞인다 → 입력 단계에서 제외한다.

## 10. 판단 경계

- 이 도구는 불법건축물 여부 확정·시정명령·과태료·고발 등 법적 판단을 하지 않는다. 의심 건 선별까지만 하며, 최종 판단은 담당자와 관할 기관이 한다.
- 의심 건을 현장 확인 대상에 올릴지는 담당자가 정한다.

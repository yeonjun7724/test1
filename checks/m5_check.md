|---|---|---|---|---|---|---|
| 1 | 중간 | `tools/m5_permit_filter.html:308` (`compare()`가 `persist()` 뒤에 `showResult()`를 호출) | 브라우저가 localStorage 접근을 막은 상태(프라이버시 설정, 일부 사내 보안 정책, 비표준 환경)에서 '대조'를 누르면 `persist()`의 `localStorage.setItem`이 예외를 던진다 | 대조 결과는 이미 계산됐지만 `showResult()`가 실행되지 않아 화면이 입력 화면에 그대로 남는다. 사용자는 버튼이 반응하지 않는 것처럼 보인다(AC5 저장 요구가 핵심 기능인 '대조'를 막음) | `persist()` 호출을 try/catch로 감싸 저장 실패가 화면 전환을 막지 않게 한다 | 남김(사유: 가상 표본 실습 범위에서는 재현 빈도가 낮고, 발생해도 새로고침·재입력으로 복구 가능) |

## 3. 실행하지 못한 확인

- 사람이 배포 주소에서 직접 '예시 불러오기'→'대조'를 눌러 S1~S3 결과를 눈으로 보는 것: AI가 사람 대신 화면을 눌러 확인할 수 없어서 못 했다. 1절에 '미검증'으로 남겼다.
- GitHub Pages 배포 확인: `tools/m5_permit_filter.html`이 아직 main에 커밋·푸시되지 않아(git 사용자 정보 미설정으로 커밋 보류) Pages 주소가 아직 없다. 커밋·푸시 뒤 다시 확인해야 한다.
- 새로고침 후 입력 복원(AC5), 백업 내보내기·가져오기(AC6): 실제 브라우저 동작 확인이 필요해 코드 검토로는 다루지 못했다.
- localStorage가 막힌 환경에서의 실제 동작: 2절 발견사항 1에서 코드상 가능성만 짚었고, 실제 그런 브라우저로 재현해 보지는 못했다.
